# Диагностические протоколы

Сверка источников выполнена 27 ноября 2026 года. Здесь описано, что означает документированный стандартный ответ. Поддержку конкретным G4FC, Vgate и прошивкой нужно подтверждать собранными ответами. Раздел [REVIEW](REVIEW.md) содержит фактические результаты программных проверок.

## Область опроса

SAE J1979 и ISO 15031-5 описывают стандартную диагностику, относящуюся к выбросам. Требования к доступности сервисов различаются по рынкам, модельным годам и типам силовой установки. Стандартное обследование не является проверкой всех автомобильных систем. [SAE J1979](https://saemobilus.sae.org/standards/j1979_201009-e-e-diagnostic-test-modes) · [ISO 15031-5:2015](https://www.iso.org/cms/live/live/en/sites/isoorg/contents/data/standard/06/63/66368.html?browse=tc)

| Чтение | Команда и начало положительного ответа | Что означает ответ |
| --- | --- | --- |
| Карта стандартных PID | `0100` → `41 00 A B C D`, затем `0120`, `0140` и следующие поддержанные страницы | Старший бит 32-битной маски для PID страницы + 1, младший для страницы + 32. Младший бит также указывает доступность следующей страницы. Если её запрос потерян, PID на ней остаются непроверенными |
| Readiness | `0101` → `41 01 A B C D` | MIL, число связанных с выбросами DTC в пределах определения PID, поддержка и готовность мониторов после очистки DTC |
| Текущая телеметрия | `01 PID` → `41 PID …` | Значение поддержанного PID. Для температуры ОЖ, оборотов и напряжения разделять свежий ответ, отсутствующий ответ и устаревшее показание |
| Сохранённые DTC | `03` → `43 …` | Подтверждённые коды, относящиеся к выбросам |
| Ожидающие DTC | `07` → `47 …` | Обнаружены в текущем или последнем завершённом цикле движения. Статус независим от `03` |
| Постоянные DTC | `0A` → `4A …` | Сохранённые постоянные коды в поддерживающем сервис ЭБУ. Стандартный формат определён для ISO 15765-4 CAN. Доступность зависит от рынка и прошивки |
| Карта параметров Freeze Frame | `020000` → `42 00 00 A B C D` | Поддержка PID для кадра 00, независимо от карты Mode 01 |
| Причина Freeze Frame | `020200` → `42 02 00 A B` | DTC, при котором сохранён кадр 00. Если `A B = 00 00`, этот ответчик сообщает об отсутствии сохранённого кадра |
| Значения Freeze Frame | `02 PID 00` → `42 PID 00 …` | Снимок при появлении DTC. Запрашивать только поддержанные и известные PID. PID и номер кадра должны совпасть с запросом |

Таблица описывает логические байты полезной нагрузки после разбора формата ELM. Поле счётчика кодов, байты заполнения, заголовки и многострочное форматирование зависят от транспорта. [ISO 15031-5:2011, §§ 7–8](https://www.iso.org/standard/50816.html) · [ISO 15031-5:2006, §§ 6.2–6.3 и 7.1–7.3, текст стандарта](https://share.qclt.com/%E6%B1%BD%E8%BD%A6%E8%AF%8A%E6%96%AD%E5%8D%8F%E8%AE%AE2/ISO-15031-5%5B1%5D.pdf) · [SAE J1979-DA 2011](https://saemobilus.sae.org/standards/j1979da_201110-j1979-da-digital-annex-e-e-diagnostic-test-modes)

### Формат и статусы ответов

- Для ISO 15765-4 после SID положительного ответа DTC следует число двухбайтовых кодов. Например, полезная нагрузка `43 01 01 33` содержит один код `P0133`, а `43 00` — явный нулевой результат от этого ответчика. В старых протоколах `03` и `07` после SID идут три пары DTC на сообщение с нулевым заполнением. Например, `43 01 33 00 00 00 00` содержит `P0133` и заполнители. SAE J1850 и ISO 9141-2 могут пропускать ответ `03` при отсутствии ошибок. Молчание не позволяет отличить этот вариант от неудачной транзакции. Формат следует выбирать по подтверждённому протоколу. Для `0A` допускается только формат ISO 15765-4. [ELM327L, с. 35–36 и 43–46](https://www.elmelectronics.com/wp-content/uploads/2016/07/ELM327L_Data_Sheet.pdf) · [SAE J1979, ред. 2007, таблица 199](https://www.autonerdz.com/yabbfiles/Attachments/1979v3.pdf)
- Формат CAF1 разбирает многострочный ответ по заявленной длине и порядку сегментов. Значение хвостовых байтов за этой длиной не задано ISO 15765-4. Их наличие не добавляет DTC. [AUTOSAR SRS CAN, § 5.2.4.3.5](https://www.autosar.org/fileadmin/standards/R4.2.2/CP/AUTOSAR_SRS_CAN.pdf)
- Без достоверного заголовка ответчик остаётся неизвестным. При нескольких ответах маски и коды нельзя приписывать конкретному физическому блоку по порядку строк. Объединённая маска отражает поддержку хотя бы одним ответчиком, если идентичность доказать нельзя. Без привязки к одному ответчику не связывать поля Freeze Frame из разных ответов в один снимок. [ISO 15031-5:2006, § 7.1.4](https://share.qclt.com/%E6%B1%BD%E8%BD%A6%E8%AF%8A%E6%96%AD%E5%8D%8F%E8%AE%AE2/ISO-15031-5%5B1%5D.pdf)
- У DTC верхние 2 бита первого байта задают семейство `P/C/B/U`, следующие 2 бита дают первый символ цифры `0…3`, оставшиеся 12 бит дают три шестнадцатеричных символа. Расшифровка требует источника для семейства, стандарта и варианта автомобиля. Для OEM-кодов сохраняются исходный код и достоверность перевода. Код не доказывает причину отказа, а причина отказа не определяется по отдельной строке. [SAE J2012 — классификация и определения DTC](https://saemobilus.sae.org/standards/j2012_202509-diagnostic-trouble-code-definitions)
- `NO DATA` сообщает об отсутствии данных у адаптера в этой транзакции. `?`, сообщение об ошибке шины, несовпадение SID/PID, отрицательный ответ `7F <SID> <NRC>`, прерывание, повреждение и отсутствие `>` должны оставаться отдельными наблюдениями. Только валидный ответ, содержащий признак нулевого результата, разрешает сообщить «код не обнаружен» для проверенного сервиса и ответчика. Отдельный тайм-аут требует восстановления синхронизации до новых запросов. [ELM327L, с. 46 и 59–64](https://www.elmelectronics.com/wp-content/uploads/2016/07/ELM327L_Data_Sheet.pdf)

### Readiness и Freeze Frame

Байт A `0101` содержит MIL в бите 7 и счётчик в битах 0–6. В B биты 0–2 задают поддержку базовых мониторов, биты 4–6 — их незавершённость. Бит 3 выбирает таблицу C/D для двигателя с искровым зажиганием или воспламенением от сжатия. В C задана поддержка каждого монитора, в D — незавершённость. Для неподдерживаемого монитора выводится «не применяется» независимо от его бита готовности. Для бензиновой таблицы редакции 2011 года бит 4 в C/D зарезервирован. Readiness описывает прогон самопроверки, а полный результат относится только к поддержанным мониторам. [SAE J1979-DA 2011, таблица B2](https://saemobilus.sae.org/standards/j1979da_201110-j1979-da-digital-annex-e-e-diagnostic-test-modes)

Карта Freeze Frame может ответить при отсутствии действительного снимка. Валидный нулевой `4202000000` означает, что кадра у ответчика нет. Если чтение не удалось, статус кадра неизвестен. ЭБУ может прислать часть значений снимка, поэтому сохраняются недостающие PID и причина неполноты. Снимок привязан к обследованию и ответчику. Его время записи остаётся неизвестным, если оно отдельно не получено из надёжного источника. [ISO 15031-5:2006, § 6.2.4.2 и § 7.2.4](https://share.qclt.com/%E6%B1%BD%E8%BD%A6%E8%AF%8A%E6%96%AD%E5%8D%8F%E8%AE%AE2/ISO-15031-5%5B1%5D.pdf)

## Ограничения адаптера и работа на машине

- Один незавершённый запрос и ограниченное обследование по действию пользователя. Временные метки начала и конца, сырые строки и причина ошибки должны сохраняться раздельно. Ответ собирается до `>` поверх фрагментов BLE. Части ответа могут прийти несколькими событиями BLE, а одна строка ELM может содержать часть многострочного ответа.
- Протокол, сообщённый `ATDPN`, нужно читать после установления связи. Префикс `A` означает автоматический выбор. Протоколы ELM 6–9 представляют варианты ISO 15765-4 CAN. Число и префикс сами по себе не подтверждают доступность какой-либо специализированной службы или GATT-профиля. [ELM327L — AT DP/AT DPN и таблица протоколов](https://www.elmelectronics.com/wp-content/uploads/2016/07/ELM327L_Data_Sheet.pdf)
- Закрытый список команд чтения. Диагностика не изменяет состояние ЭБУ. Запросы очистки, программирования, тестов исполнительных механизмов, управления сессиями, доступа к защищённым сервисам и произвольная пользовательская команда запрещены. Настройка ELM для штатного обмена относится к адаптеру.
- При переполнении, отмене, потере транспорта или нарушении фрейминга прекратить обследование и сохранить уже полученные данные как частичные. Восстановить штатную телеметрию через синхронизированное соединение.
- Проверять каждый тип состояния с безопасно припаркованным автомобилем, на открытом воздухе при работающем двигателе. Записывать состояние зажигания и двигателя. Скорость 0 и отсутствие ответа отражают разные состояния.

## Шлюз для новых блоков

Профиль расширенной диагностики должен закреплять конкретный рынок, кузов, блок и версию, документацию производителя к адресации и транспорту, точный запрос чтения, ответ и ограничения на безопасный сценарий. Источник и применимость проверяются до включения профиля. Во время испытания на неподвижной машине включается один подтверждённый профиль с конечным числом запросов, временем ожидания и явным прекращением при конфликте. Если документация или профиль отсутствуют, блок обозначается как «не обследован», запросов к нему нет. Принятые от стандартного опроса идентификаторы допустимо использовать как наблюдения для анализа, присвоить им имя ABS/ESP, SRS, EPS или BCM можно только после подтверждения для этой машины. [Hyundai Global Service Way](https://gsw.hyundai.com/) · [ISO 15031-5 — диагностика выбросов](https://www.iso.org/cms/live/live/en/sites/isoorg/contents/data/standard/06/63/66368.html?browse=tc)

## Фон и CarPlay

CoreBluetooth может разбудить приложение для предусмотренных BLE-событий в соответствующем фоновом режиме. Приостановка приложения и объединение событий сканирования ограничивают доступную частоту, восстановление состояния требует явной реализации и зависит от завершения процесса. Непрерывная выборка, подключение после принудительного закрытия и сбор данных до появления iPhone рядом с адаптером остаются за границами гарантии. [Apple — Core Bluetooth Background Processing](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html)

Apple предоставляет CarPlay-поверхности для WidgetKit `systemSmall` и ActivityKit `ActivityFamily.small`. Место вывода выбирает система, а обновление WidgetKit ограничено системным бюджетом. Поверхности читают опубликованный снимок и его время. Они не владеют BLE-соединением и должны показывать устаревание при его потере. Физический CarPlay и доступ к общему контейнеру после подписи остаются UNVERIFIED для диагностической сборки. [Apple — CarPlay for Developers](https://developer.apple.com/carplay/) · [Apple — Creating custom views for Live Activities](https://developer.apple.com/documentation/ActivityKit/creating-custom-views-for-live-activities) · [Apple — Keeping a widget up to date](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date)

## Уровни подтверждения

| Уровень | Что считается доказательством |
| --- | --- |
| Документировано | Таблица стандарта, спецификация адаптера или документация производителя для проверяемого варианта |
| Проверено программно | Фиксированный набор ответов, который проверяет формат, статусы отсутствия, отказов, несколько ответчиков и обработку разрыва. Конкретные прогоны указаны в [REVIEW](REVIEW.md) |
| UNVERIFIED | Конкретный G4FC, Vgate, поддержка PID, получение Freeze Frame, доступность других блоков, работа при блокировке и CarPlay до прогона на автомобиле |
