# Движок мониторинга 0.9

Движок принимает кадры Swift, переигрывает их без BLE, SwiftUI и SQLite, а затем возвращает состояния, наблюдения и переходы для журнала. Профиль Hyundai Elantra HD 2011 G4FC 1.6 МКПП имеет идентификатор и версию. У правила есть независимая версия. Событие сохраняет идентификатор правила и версии, важность, режим, измерения с происхождением и время. Подробные формулы и источники приведены в [каталоге правил](DIAGNOSTIC_RULES.md).

## Оценка

- Кадр содержит монотонное время, UTC, наблюдаемые PID и, при наличии, идентификатор записываемого периода. Каждый PID несёт собственные время и качество. Движок может получать последние отсчёты повторно. Они не становятся новыми измерениями.
- Условия применимости состоят из выражений `all` и `any`, доступности показаний, режима, согласованности времён и состояния контура. Предикаты поддерживают сравнения отсчётов, скользящих агрегатов, сумм, разностей и сравнений с собственной медианой и MAD.
- Каждое окно имеет максимальную длину, минимальное число уникальных отсчётов, минимальное покрытие и максимальную паузу между отсчётами. Окно ограничено текущим режимом. Для снижения температуры и её размаха окно охватывает текущий непрерывный период работы двигателя, чтобы охладившийся отсчёт можно было сравнить с предыдущими. Окна топливных коррекций дополнительно ограничены непрерывным замкнутым контуром. Агрегаты показывают свойства записанных точек. Например, среднее по точкам не оценивает пропущенную часть интервала.
- Открытие и восстановление требуют отдельно заданных условий и длительности. Время не растёт от повторного отсчёта и не склеивается через срок его свежести. Потеря BLE, смена периода, откат монотонного времени и пауза более шести секунд сбрасывают непрерывность. При нехватке данных прежняя проблема остаётся открытой. Новые условия восстановления требуют свежих отсчётов.
- Включение и отключение правила сохраняется. Отключение останавливает оценку и сохраняет прежнюю проблему. При изменении пользовательского температурного порога существующая проблема использует порог открытия для оценки восстановления.
- Событие имеет собственный UUID, общий UUID открытия и восстановления и UUID группы связанных проблем. Корреляция группирует наблюдения с общей предметной областью. Связь с DTC означает совпадение темы и доступного кода на момент оценки. Уведомление предлагается при открытии активного правила, блок повторов 15 минут на группу. Рост важности до критического допускается отдельно. Восстановление остаётся событием журнала.
- Контрольная точка версии 1 хранит открытые проблемы, настройки правил, статистику и отметки уведомлений. Восстановление приложения не переносит время ожидания или скользящие окна между процессами. Длительность проблемы после разрыва измерений неизвестна.

## Значение статусов

| Статус | Интерпретация |
| --- | --- |
| Недостаточно данных | Отсутствуют достоверные условия, свежий отсчёт или покрытие окна. Открытая проблема остаётся доступна в журнале |
| Не применимо | Правило отключено или достоверно установлено другое условие эксплуатации |
| Наблюдение | Доступна наблюдаемая метрика либо формируется экспериментальный вывод |
| Условие не сработало | Проверен конкретный триггер с доступными входами |
| Отклонение | Входы находятся за границей активного условия либо пора проверить экспериментальное наблюдение |
| Проблема | Активный триггер достиг требуемой выдержки |
| Восстановление | Последовательно выполнены условия восстановления открытой проблемы |

Движок не выполняет действий с ЭБУ. Он потребляет те же данные, которые используются для записи поездок. Сведения о доступности сервисов OBD относятся к фактически ответившим блокам. [Подтверждённые команды](DIAGNOSTIC_PROTOCOLS.md)

## Проверка

Регрессии покрывают потерю свежести между кадрами, падение соединения, восстановление открытого состояния, корреляцию, подавление повторного уведомления, поведение после изменения порога, независимые скользящие окна, режим смеси, позднее подключение, происхождение напряжения ATRV, несколько сопоставимых поездок и исключение проблемного периода из выборки. Аппаратная достоверность наблюдений остаётся отдельным испытанием.
