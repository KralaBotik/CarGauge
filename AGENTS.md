# CarGauge — инструкции для разработки

## Границы проекта

- Работать только в этом репозитории. Не менять соседние проекты и глобальные настройки инструментов.
- Нативный Swift / SwiftUI. iPhone → CoreBluetooth → Vgate iCar Pro BLE → ELM327 → OBD-II.
- Автомобиль для проверки: Hyundai Elantra HD, G4FC. Поддержку PID и BLE UUID подтверждать на реальном экземпляре.
- Среда разработки — Linux; iOS SDK и Xcode запускаются только в macOS CI. Не выдавать Linux-проверку за сборку iOS.

## Порядок реализации

- Сначала воспроизводимый симулятор, затем тот же протокол транспорта для BLE.
- `Sources/CarGaugeCore` не зависит от Apple UI/Bluetooth frameworks и тестируется через `swift test` на Linux.
- UI и CoreBluetooth изолировать `@MainActor`; отмена операции должна завершать continuation ровно один раз.
- ELM327 допускает только одну незавершённую команду. Ответ заканчивается `>`, а не границей BLE-пакета.
- После тайм-аута/потери синхронизации пересоздавать соединение; запоздавший ответ не должен стать ответом следующей команды.
- Отправлять только разрешённые AT-команды настройки и Mode 01 PID. Не стирать DTC и не управлять ECU.
- Хранить время каждого измерения. Пропавшие/устаревшие данные не представлять как текущие или как 0.
- `0142` — напряжение ECU, `ATRV` — оценка напряжения адаптером. Источник всегда виден пользователю.
- Пороги перегрева прототипа не являются заводской спецификацией Hyundai; использовать гистерезис и отмечать это в UI/документации.
- Симуляционные данные явно маркировать во всех UI, виджетах и Live Activity.

## CarPlay и фон

- Проверять новые утверждения по официальной документации Apple; сохранять ссылки и дату проверки в `docs/PLATFORM.md`.
- Использовать WidgetKit `systemSmall` и ActivityKit small family. Не добавлять CarPlay entitlement без основания и одобрения Apple.
- Не обещать произвольный экран CarPlay, гарантированную частоту WidgetKit или непрерывную работу приложения в фоне.
- Live Activity и виджет не владеют BLE-соединением. При отсутствии свежих данных они должны показывать это явно.

## Проверки

- `swift test` — парсер, фрейминг, ELM-сессия, симулятор, свежесть, предупреждения и ограничение истории.
- `swift run cargauge-simulator` — воспроизводимый сквозной сценарий без iPhone.
- `python3 scripts/validate_project.py` — согласованность проекта/entitlements/plist.
- macOS: `scripts/ci-ios.sh` — XcodeGen, simulator UI smoke tests и unsigned device build.
- После изменений провести ревью, исправить найденные дефекты и записать фактические результаты и непроверенные области в `docs/REVIEW.md`.
- Не добавлять секреты подписи в Git. Не утверждать, что удалённый CI прошёл, без результата соответствующего запуска.
